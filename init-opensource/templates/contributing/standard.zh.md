## 我有一个问题

> 如果您想提问，我们假设您已经阅读了可用的[文档]([Documentation URL])。

在提问之前，最好搜索现有的[Issues]([Repository URL]/issues)，看看是否能找到帮助。如果您找到了合适的问题但仍需要澄清，可以在该问题中写下您的问题。此外，建议先在互联网上搜索答案。

如果您仍然觉得需要提问并需要澄清，我们建议您：

- 提交一个[Issue]([Repository URL]/issues/new)。
- 提供尽可能多的关于您遇到的问题的上下文。
- 提供项目和平台版本（nodejs、npm 等），视情况而定。

我们将尽快处理该问题。

## 我想贡献

> ### 法律声明 <!-- omit in toc -->
> 为本项目做出贡献时，您必须同意您创作了 100% 的内容，您拥有该内容的必要权利，并且您贡献的内容可以在项目许可下提供。

### 报告 Bug

<!-- omit in toc -->
#### 在提交 Bug 报告之前

一个好的 Bug 报告不应该让其他人需要追着您要更多信息。因此，我们要求您仔细调查，收集信息，并在报告中详细描述问题。请提前完成以下步骤，以帮助我们尽快修复任何潜在的 Bug。

- 确保您使用的是最新版本。
- 确定您的 Bug 是否真的是 Bug，而不是您这边的错误，例如使用不兼容的环境组件/版本（请确保您已经阅读了[文档]([Documentation URL])）。如果您在寻求支持，可能需要查看[本节](#我有一个问题)。
- 要查看其他用户是否遇到过（并可能已经解决了）与您相同的问题，请检查在[问题跟踪器]([Repository URL]/issues?q=label%3Abug)中是否已有针对您的 Bug 或错误的现有报告。
- 还要确保搜索互联网（包括 Stack Overflow），看看 GitHub 社区之外的用户是否讨论过这个问题。
- 收集有关 Bug 的信息：
  - 堆栈跟踪（Traceback）
  - 操作系统、平台和版本（Windows、Linux、macOS、x86、ARM）
  - 解释器、编译器、SDK、运行时环境、包管理器的版本，视情况而定。
  - 可能的输入和输出
  - 您能可靠地重现这个问题吗？您也能用旧版本重现它吗？

<!-- omit in toc -->
#### 如何提交一个好的 Bug 报告？

> 您绝不能将安全相关的问题、漏洞或包含敏感信息的 Bug 报告给问题跟踪器或公开的其他地方。相反，敏感 Bug 必须通过电子邮件发送至 <[Security Email]>。
<!-- 您可以添加 PGP 密钥，以便消息也能加密发送。 -->

我们使用 GitHub issues 来跟踪 Bug 和错误。如果您遇到项目的问题：

- 提交一个[Issue]([Repository URL]/issues/new)。（由于我们此时还不能确定这是否是 Bug，我们要求您暂时不要谈论 Bug，也不要标记该问题。）
- 解释您期望的行为和实际行为。
- 请提供尽可能多的上下文，并描述其他人可以遵循的*重现步骤*，以便在他们自己的环境中重现该问题。这通常包括您的代码。对于好的 Bug 报告，您应该隔离问题并创建一个精简的测试用例。
- 提供您在上一步中收集的信息。

提交后：

- 项目团队将相应地标记该问题。
- 团队成员将尝试使用您提供的步骤重现该问题。如果没有重现步骤或没有明显的方法重现该问题，团队将向您询问这些步骤，并将该问题标记为 `needs-repro`。带有 `needs-repro` 标签的 Bug 在被重现之前不会被处理。
- 如果团队能够重现该问题，它将被标记为 `needs-fix`，以及可能的其他标签（例如 `critical`），该问题将被留给[某人实现](#您的第一次代码贡献)。

### 建议改进

本节指导您为 [Project Name] 提交改进建议，**包括全新功能和对现有功能的小改进**。遵循这些指南将帮助维护者和社区理解您的建议并找到相关建议。

<!-- omit in toc -->
#### 在提交改进之前

- 确保您使用的是最新版本。
- 仔细阅读[文档]([Documentation URL])，看看功能是否已经被涵盖，可能是通过单独的配置。
- 进行[搜索]([Repository URL]/issues)，看看该改进是否已经被建议。如果已经建议，请在现有问题上添加评论，而不是打开一个新问题。
- 了解您的想法是否符合项目的范围和目标。您有责任向项目开发者充分说明该功能的价值。请记住，我们希望功能对大多数用户有用，而不仅仅是少数用户。如果您只针对少数用户，请考虑编写一个附加组件/插件库。

<!-- omit in toc -->
#### 如何提交一个好的改进建议？

改进建议作为 [GitHub issues]([Repository URL]/issues) 进行跟踪。

- 使用**清晰且描述性的标题**来标识建议。
- 尽可能详细地提供**改进建议的逐步描述**。
- **描述当前行为**并**解释您期望看到的行为**以及原因。此时您还可以告诉我们哪些替代方案对您不起作用。
- 您可能想**包含截图或屏幕录制**，以帮助演示步骤或指出建议相关的部分。您可以在 macOS 和 Windows 上使用 [LICEcap](https://www.cockos.com/licecap/) 录制 GIF，在 Linux 上使用 GNOME 内置的[屏幕录制器](https://help.gnome.org/users/gnome-help/stable/screen-shot-record.html.en)或 [SimpleScreenRecorder](https://github.com/MaartenBaert/ssr)。<!-- 仅在项目有 GUI 时才包含此项 -->
- **解释为什么这个改进对大多数 [Project Name] 用户有用**。您可能还想指出其他更好地解决这个问题的项目，它们可以作为灵感来源。
